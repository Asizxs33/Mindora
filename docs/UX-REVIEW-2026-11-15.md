# Mindora scenario and interface review — 15 November 2026

This is an expert review with browser scenarios and automated checks. It does not claim interviews or usability sessions with real participants. The target remains working adults who want a short, useful lesson and an easy return to unfinished work.

## Findings and changes

| Priority | Journey | Observed problem | Change and verification |
| --- | --- | --- | --- |
| High | Find tools on a phone | Work, practice, achievements and rewards were all inside a closed “Learning & progress” disclosure. | Four labeled, directly visible actions. Account controls stay above them; settings have their own visible heading. Checked in EN/RU/KK at phone and tablet widths. |
| High | Guest library | A guest who could already study was shown a misleading sign-in-to-start gate above local courses. | The guest library shows local courses directly. Optional account creation stays in Profile; the sign-in gate remains available for contexts that require it. |
| High | Choose a course | The ready-course catalog was closed by default, including when there were no personal courses. | Show the catalog directly. Separate “Continue learning” from the ready courses and keep errors, loading and imports visible. |
| High | Resume a later lesson | On a cold phone reload, the current step could remain below the fixed navigation. An early scroll ran before page layout was ready. | Reveal the current step after initial loading, with the phone navigation included in the visible bounds. Tested a fourth-step checkpoint after reload. |
| High | Leave a built-in lesson | Exit opened a different, older map layout. | Return to the same built-in journey. The saved lesson cursor and drafts remain controlled by core. |
| Medium | Change screen size while creating | Widening the browser redirected Create to Learn, removing the visible creation form. | Keep the creation route when crossing the phone/desktop breakpoint. Existing composer tests verify node, value, selection and position during background updates. |
| Medium | Find an existing course | A growing course library had no title search. | Search saved and ready courses together, with a useful empty result and Clear action. Preserve query, keyboard focus and caret during a delayed refresh; reset it on account change. |
| Medium | Read balances | Streak, gems and lives had framed cells, separators and conflicting colors. | Remove frames, tile backgrounds and dividers. Use matching orange SVG outlines/fills and readable numeric balances. Keep full accessible labels, keyboard focus and minimum 44 px counter targets. |

The desktop study workspace remains a menu, central course path and separate activity rail. Phone navigation stays Courses/Profile, with Path/Saved/Create as visible course tabs. Course content is allowed to scroll naturally. Essential navigation is not placed behind a generic More button.

## Verification performed

| Scenario | Boundary and evidence |
| --- | --- |
| Responsive navigation, search, profile tools, rewards, work and resume | Real browser renderers with explicit API fixtures. Widths 320, 390, 640 landscape, 768, 1024, 1440 and 1920; EN/RU/KK. `scripts/verify-ux-journey.mjs`. Includes claiming a quest, buying a freeze, search recovery, background refresh and a later saved step. |
| Guest start, AI roadmap, generated lesson, correct/incorrect answer, completion and next lesson | `scripts/verify-public-browser.mjs` and `scripts/verify-guided-browser.mjs`. API fixtures are explicit. Checks also cover 5/10/20-minute courses, recall/repair, signout/signin and restored drafts. |
| Live AI generation and interrupted study | On the existing public site, a fresh phone guest created a household-budget roadmap and its first lesson through real APIs. Clarification, roadmap and lesson requests returned HTTP 200. Closing the page and reopening preserved the exact lesson text and page, without another lesson-generation request. This checks the published backend, not publication of this new UI patch. |
| Poster and spreadsheet editors | `scripts/verify-ux-editors.mjs`: 320 and 1440 px, rejected incomplete/incorrect work, corrected it, saved the work and downloaded SVG/CSV through the actual UI/controller. Account/workspace services use fixtures. |
| Characters, explanations, account panels and reduced motion | `scripts/verify-mentor-layout.mjs`: 899 geometry checks, six mentors and their poses, fallback extremes, ten lesson templates, four viewport sizes and reduced motion. |
| Creating on different devices and delayed account/library responses | `scripts/verify-mobile-home.mjs`: 23 checks including preserved editing nodes, caret, value and screen position, no horizontal overflow and accessible signout. |
| Course-search edge cases | Unit tests cover saved/ready titles, word order, Unicode case/normalization, no results, clearing, and keeping loading/errors/imports accessible. |

The review used [Nielsen’s usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) for discoverability, consistency and recovery, and [WCAG 2.2](https://www.w3.org/TR/WCAG22/) for reflow, visible focus and unobscured controls. These checks are not a claim of complete WCAG conformance.
